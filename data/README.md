# `data/` — Datasets

This folder holds the four public datasets used in the study and the
preprocessed splits generated from them. The raw files are **not
redistributed** in the public repository (size and source licensing); obtain
them from the sources below and place them here with the exact filenames
shown. `notebook 01` auto-downloads only `german.data`.

## Expected layout

```
data/
├── german.data                 # UCI Statlog (German Credit) — auto-downloaded by 01
├── application_record.csv      # Kaggle: Credit Card Approval Prediction (features)
├── credit_record.csv           # Kaggle: Credit Card Approval Prediction (monthly status)
├── insurance.csv               # Kaggle: Medical Cost Personal
├── porto_train.csv             # Kaggle: Porto Seguro Safe Driver (competition train.csv, renamed)
└── processed/                  # generated by notebook 02 (do not edit by hand)
    ├── <dataset>.parquet               # intermediate frame from notebook 01
    ├── <dataset>_train.parquet         # stratified train split
    ├── <dataset>_test.parquet          # stratified test split
    └── preprocess_meta.json            # targets, sensitive columns, split config
```

`<dataset>` is one of: `german`, `credit_card_approval`, `insurance`,
`porto_seguro`.

## Raw datasets

### 1. German Credit (Statlog) — *credit domain*
- **File:** `german.data`
- **Source:** UCI Machine Learning Repository, *Statlog (German Credit Data)*.
  Downloaded automatically by `notebooks/01_data_loading.ipynb` if absent.
- **Target:** credit risk; recoded here to `1 = bad (default)`, `0 = good`.
- **Sensitive attributes:** `sex` (mapped from the combined
  personal-status-and-sex code), `age_group` (`old` if age ≥ 25).
- **Note:** the widely used UCI release has a documented coding issue in the
  combined sex/marital-status variable; the sex attribute inherits this
  limitation (see the manuscript's Limitations). The corrected "South German
  Credit" release is **not** used here.

### 2. Credit Card Approval Prediction — *credit domain*
- **Files:** `application_record.csv` (applicant features),
  `credit_record.csv` (monthly repayment status).
- **Source:** Kaggle, *Credit Card Approval Prediction*.
- **Target:** derived from the monthly `STATUS` codes. The primary label
  `target_30dpd` marks an account as high-risk if it ever reaches 30+ days
  past due (`STATUS ∈ {1,2,3,4,5}`); `target_60dpd` uses the 60+ day
  threshold and is retained for optional threshold sensitivity.
- **Sensitive attribute:** `sex` (from `CODE_GENDER`).

### 3. Medical Cost Personal — *insurance domain*
- **File:** `insurance.csv`
- **Source:** Kaggle, *Medical Cost Personal Datasets*.
- **Target:** the continuous `charges` column is binarized into an
  underwriting-style label — `1` if `charges` is in the top quartile (≥ 75th
  percentile), else `0`.
- **Sensitive attributes:** `sex`, `age_group` (`old` if age ≥ 40),
  `smoker_flag`.

### 4. Porto Seguro Safe Driver Prediction — *insurance domain*
- **File:** `porto_train.csv` (the competition `train.csv`, renamed).
- **Source:** Kaggle competition, *Porto Seguro's Safe Driver Prediction*.
- **Target:** `target` = whether a claim was filed.
- **Sensitive attributes:** none explicit. The anonymized individual-level
  proxy variables `ps_ind_*` (categorical/binary) are treated as sensitive;
  `ps_ind_04_cat` is the representative proxy and the remainder are analyzed
  as a worst-case, significance-gated set.
- **Missing values:** the competition encodes missing as `-1`; this is
  converted to `NaN` in `notebook 01`.

## How `processed/` is generated

`notebooks/02_preprocessing.ipynb` applies one shared routine to every
dataset: median imputation + standardization for numeric features, a
`"missing"` category + one-hot encoding for categoricals (all fit on the
train split only), a stratified 25% test split (`random_state = 42`), and a
common row cap of 40,000 (stratified subsample) for the large Porto Seguro
set so sample-size differences do not confound the cross-domain comparison.
Running notebooks `01` then `02` regenerates everything in `processed/`;
these files are build artifacts and should not be edited by hand.
