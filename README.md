# Cross-Domain AI Governance Gap Analysis — Replication Code

Replication code for the manuscript *"Cross-Domain AI Governance Gap Analysis:
Comparing Fairness Gaps between Credit Scoring and Insurance Underwriting under
High-Impact AI Standards."*

## Overview

The study introduces the **Governance Gap Index (GGI)**, which measures how far a
deployed model falls short of a regulation's thresholds along four axes —
discriminative performance, worst-case disparate impact, worst-case statistical
parity, and explainability — and compares the gap across two high-impact AI
domains (credit scoring, insurance underwriting) and three regulatory regimes
(KR AI Basic Act, EU AI Act, US NAIC).

This version computes a **noise-corrected GGI**. Because a weak (near-chance)
model combined with many candidate proxy attributes can inflate the worst-case
fairness axis — taking the minimum disparate impact over many noisy, sometimes
very small subgroups selects extreme values that pure noise reproduces, a floor /
multiple-comparison artifact — the worst-case fairness axis is **gated by
statistical significance**:

* for each sensitive attribute, a two-sided permutation test on the group
  difference in positive-prediction rate yields a p-value;
* Benjamini–Hochberg (FDR < 0.05) controls multiplicity within a dataset;
* the worst case is taken only over attributes that remain significant; if none
  do, the axis scores parity (no evidence of disparity).

The performance axis is reported together with a label-permutation p-value for
AUC > 0.5, so a weak-but-significant model is distinguished from one that is
indistinguishable from chance. The original (all-proxy) GGI is also produced for
side-by-side comparison.

## Data

The datasets are public but are **not redistributed** here (size and source
licensing). Download them and place the files in `data/`:

| File in `data/`            | Source |
|----------------------------|--------|
| `german.data`              | UCI Statlog (German Credit Data) — auto-downloaded by notebook 01 if absent |
| `application_record.csv`, `credit_record.csv` | Kaggle: Credit Card Approval Prediction |

network (once), and only if it is missing.

## Reproducing the results

```bash
python -m venv .venv && source .venv/bin/activate   # optional
pip install -r requirements.txt

# run the notebooks in order (from the notebooks/ folder)
cd notebooks
for nb in 01_data_loading 02_preprocessing 03_fairness_metrics \
          04_ggi 05_sensitivity 06_visualization 07_recourse; do
  jupyter nbconvert --to notebook --execute --inplace "$nb.ipynb"
done
```

Each notebook is a single code cell, reads from / writes to the folders above
using relative paths, and regenerates the tables in `results/tables/` and the
figures in `results/figures/`. Notebooks 01–05 are deterministic
(`random_state = 42`); notebook 07 (DiCE counterfactual search) is the slowest
step.

## Notes on reproducibility

* All randomness is seeded (`random_state = 42`); the permutation tests use
  2000 permutations (fairness) and 500 (AUC), and the bootstrap uses 200
  resamples.
* Package versions are pinned in `requirements.txt`. Results are numerically
  stable but may vary at the last decimal with different BLAS / library builds.
* The large insurance dataset (Porto Seguro) is stratified-subsampled to a
  common row cap in notebook 02 so that sample-size differences do not confound
  the cross-domain comparison. Because the subsample depends on the library
  version's grouped-sampling behaviour, the exact composition of a few very
  small proxy subgroups can shift between environments; the significance gating
  is designed to be robust to this.
